# 性能报告 — 赛道B 检测引擎

> 本报告由 `python selftest/run_selftest.py` 实测产出；数字将在自测运行后填入（见文末「实测数据」）。测量方法：`time.perf_counter` 计运行时间、`tracemalloc` 计 Python 对象峰值内存。

## 1. 资源约束（题目 §4）与性能维度

| 约束 | 值 | 本引擎 |
|------|------|------|
| 计算资源 | 4 vCPU / 8 GB 内存 | 单线程 ~11 ms/skill、峰值 Python 对象内存 <1 MiB |
| 总时限 | 30 min（超时按已完成部分计分） | 全局 28 min 预算守卫 + 流式落盘，保证完成与部分计分 |
| 镜像大小 | ≤ 10 GB | `python:3.11-slim` + 纯 stdlib 引擎，约百 MB 级 |
| 网络 | 评测期完全隔离 | 引擎零出网、零外部 API |

> 性能维度 = **检测速度 × Token 效率**。本引擎**不使用任何 LLM/外部 API → Token 消耗 = 0**，Token 效率达满；检测速度远在 30 min 限内（见 §3/§4）。可选的离线注入分类器仅在灰区触发且镜像内置模型时启用，缺省不加载，性能不受影响。

## 2. 复杂度与设计预算

- **单遍扫描**：每个文件只构造一次归一化视图，所有 regex 在该视图上各扫一遍；无重复读取。
- **预编译 regex**：导入期编译，均为**有界量词**（`{0,N}`），无嵌套 `(.*)+`，ReDoS 安全。
- **共现判定**：用匹配的字符 offset 做整数比较，非嵌套扫描。
- **流式写出**：逐 skill 产出即写一行，结果不全量驻留内存。
- **熵计算**：仅对有界的候选 blob 片段计算。

粗略预算：350 个样本 × ~33 KB ≈ 11.5 MB 文本，约 30 条 regex ≈ 10^8 量级字符操作 → 亚秒级。引擎本体相对 `t_ref=600s` 有约两个数量级余量；峰值内存为「解释器 + 单文件缓冲 + 编码后的模型字典」量级，远低于 `m_ref=4096MB`。

即便语料放大 100×（~1.15 GB，流式、不全驻留），运行时间与内存仍应落在 `t_max`/`m_max` 之内。

## 3. 实测数据（自测语料 347 样本，本机 Python 3.11.9，2026‑06‑14，升级后）

| 指标 | 实测值 | §4 约束 | 结论 |
|------|--------|------|------|
| 总运行时间 | **~5.9 s** | 30 min 总时限 | ✅ 约 1/300，余量充裕 |
| 单样本平均 | **~16.9 ms/skill** | — | 单线程约 60 skills/s |
| 峰值内存 (tracemalloc) | **~0.7 MiB** | 8 GB | ✅ 远低于上限 |
| Token 消耗 | **0** | — | 无 LLM → Token 效率满分 |

> 升级后新增 prose 注入/manifest 结构化/同形字还原/递归解码/灰区语义，单样本耗时略增（~15→17 ms）但仍极快。`tracemalloc` 仅统计 Python 对象峰值，未含解释器常驻 RSS（slim 解释器 + 编译 regex + 模型字典，约数十 MB），合计远低于 8 GB。同形字还原仅在检出同形字时触发、递归解码有 blob 数/字节上限，均不构成性能风险。

## 4. 规模外推（单线程线性）

| 样本数 | 预计运行时间 | 对照 30 min 总时限 |
|--------|-------------|------|
| 347 | ~5.9 s（实测） | ≪ 30 min |
| 3,500 | ≈ 60 s | ≪ 30 min |
| 35,000 | ≈ 10 min | < 30 min |
| ~100,000 | ≈ 28 min | ≈ 预算守卫触发点（剩余走规则快路） |

引擎对每个 skill 的处理彼此独立、无全局聚合，运行时间随样本数近似线性，内存恒定。常见规模（数百至数千样本）耗时数秒到一分钟；逼近 10 万级时全局时间预算守卫（28 min）会让尾部样本走规则‑only 快路，配合流式落盘保证 30 min 内完成且每个 skill 均有结果行（对齐 §4「超时按已完成部分计分」）。

> 备注：当前为确定性单线程实现（利于复现与排查）。若 holdout 规模极大需要提速，可在保持逐样本确定性的前提下做进程级并行（每 skill 独立、无共享状态），但默认不开启以最大化可复现性。
