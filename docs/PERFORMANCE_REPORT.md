# 性能报告 — 赛道B 检测引擎

> 本报告由 `python selftest/run_selftest.py` 实测产出；数字将在自测运行后填入（见文末「实测数据」）。测量方法：`time.perf_counter` 计运行时间、`tracemalloc` 计 Python 对象峰值内存。

## 1. 公开阈值对照

| 参数 | 阈值 | 含义 |
|------|------|------|
| t_ref | 600 s | 运行时间 ≤ 此值 → 运行维度满分 |
| t_max | 7200 s | 运行时间 ≥ 此值 → 运行维度为零 |
| m_ref | 4096 MB | 参考峰值内存 |
| m_max | 16384 MB | 峰值内存 ≥ 此值 → 内存维度为零 |

## 2. 复杂度与设计预算

- **单遍扫描**：每个文件只构造一次归一化视图，所有 regex 在该视图上各扫一遍；无重复读取。
- **预编译 regex**：导入期编译，均为**有界量词**（`{0,N}`），无嵌套 `(.*)+`，ReDoS 安全。
- **共现判定**：用匹配的字符 offset 做整数比较，非嵌套扫描。
- **流式写出**：逐 skill 产出即写一行，结果不全量驻留内存。
- **熵计算**：仅对有界的候选 blob 片段计算。

粗略预算：350 个样本 × ~33 KB ≈ 11.5 MB 文本，约 30 条 regex ≈ 10^8 量级字符操作 → 亚秒级。引擎本体相对 `t_ref=600s` 有约两个数量级余量；峰值内存为「解释器 + 单文件缓冲 + 编码后的模型字典」量级，远低于 `m_ref=4096MB`。

即便语料放大 100×（~1.15 GB，流式、不全驻留），运行时间与内存仍应落在 `t_max`/`m_max` 之内。

## 3. 实测数据（自测语料 347 样本，本机 Python 3.11.9，2026‑06‑13）

| 指标 | 实测值 | 阈值 | 结论 |
|------|--------|------|------|
| 总运行时间 | **5.094 s** | t_ref 600 s | ✅ 约 1/118，满分区间 |
| 单样本平均 | **14.68 ms/skill** | — | 单线程约 68 skills/s |
| 峰值内存 (tracemalloc) | **0.68 MiB** | m_ref 4096 MB | ✅ 远低于参考 |

> 说明：`tracemalloc` 仅统计 Python 对象分配峰值（0.68 MiB），未含解释器常驻 RSS（python:3.11-slim 解释器 + 编译 regex + 173 KB 模型字典，量级约数十 MB），二者合计仍远低于 `m_ref=4096MB`。容器内 RSS 可用 `/usr/bin/time -v` 复核。

单样本耗时主要来自 ML 推理（分词 + TF‑IDF）与 ~30 条 regex 扫描；内存与样本数无关（逐样本处理、流式写出）。

## 4. 规模外推（单线程线性）

| 样本数 | 预计运行时间 | 对照 |
|--------|-------------|------|
| 347 | 5.1 s（实测） | — |
| 3,500 | ≈ 51 s | ≪ t_ref 600 s |
| 35,000 | ≈ 8.6 min（514 s） | < t_ref 600 s |
| 50,000 | ≈ 12.2 min（734 s） | 略超 t_ref、远 < t_max 7200 s |
| 350,000 | ≈ 86 min | ≪ t_max 7200 s |

引擎对每个 skill 的处理彼此独立、无全局聚合，运行时间随样本数近似线性，内存恒定（不随样本数增长）。即便面对超大 holdout，也稳处 `t_max`/`m_max` 之内；对常见规模（数百至数千样本）则落在 `t_ref` 满分区间。

> 备注：当前为确定性单线程实现（利于复现与排查）。若 holdout 规模极大需要提速，可在保持逐样本确定性的前提下做进程级并行（每 skill 独立、无共享状态），但默认不开启以最大化可复现性。
